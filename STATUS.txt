  DEFERRED to its next eligible time, never dropped.

  BROKEN THINGS FOUND AND FIXED — none of these were in this file:
  1. app.py hardcoded SCORING_MODEL = "north-64k", removed from the machine long ago.

     indefinitely rather than naming the missing model. THE CLIP FINDER HAD BEEN DEAD.
  2. profile.py at the project root shadowed Python's stdlib `profile` module. The root
     is sys.path[0] whenever ClipForge runs from its own folder, which RUN_PIPELINE.bat
     does, so torch's import of cProfile got the channel profile and took the entire GPU
     stack down. Renamed to channel.py. tests/test_twin.py now scans the root against
     every stdlib name, and that check is proven to FAIL against the old layout.
  3. All three test suites hardcoded a pre-move absolute path to the project. Every one
     had failed to import since the folder moved, so CHECK_EVERYTHING.bat — the one
     button that says whether ClipForge works — had been unable to say. Now relative.
  4. faster-whisper was listed in requirements.txt but was not installed, and the CUDA
     runtime libraries it needs were absent.

  INSTALL TRAP, worth reading before touching the environment:
  chatterbox-tts pins torch==2.6.0 and LatentSync pins torch==2.5.1. On this Blackwell
  card either pin silently installs a PROCESSOR-ONLY torch. Nothing errors; it is simply
  about twenty times slower forever. Always re-pin afterwards:
      pip install --force-reinstall torch==2.11.0 torchaudio==2.11.0 \
          --index-url https://download.pytorch.org/whl/cu128
  and confirm with: python -c "import torch; print(torch.cuda.is_available())"
